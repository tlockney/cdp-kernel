Jupyter kernel · TypeScript · JavaScript runtimes

TypeScript notebooks on the runtime you choose.

cdp-kernel is Deno's Jupyter kernel, extracted so the code in your cells can run on Node, Deno, Bun, workerd or celld. The kernel speaks the Jupyter protocol; your cells run in the runtime you pick.

Try it on Binder View on GitHub

Binder opens a notebook in your browser with nothing to install. Or install it, or open it in Codespaces.

# Node 22.18+ host
npm install -g @tlockney/cdp-kernel
cdp-kernel install --runtime node
# or deno, bun, workerd, celld
# Deno host
deno run -A jsr:@tlockney/cdp-kernel/cli \
  install --runtime deno
# JupyterLab, every runtime, the examples
docker run --rm -p 8888:8888 ghcr.io/tlockney/cdp-kernel

Write a cell, pick a runtime

Each install writes a kernelspec (cdp-node, cdp-deno, cdp-bun, …). Choose it in JupyterLab or VS Code and write TypeScript. Imports from npm and JSR install on first use.

Cells display rich output through a global jupyter: jupyter.display, md, html, svg, image, and Symbol.for("Jupyter.display") for your own types. It is ported from Deno's Deno.jupyter, which is the same object on cdp-deno.

Features

TypeScript, as in deno jupyter

TS, TSX, enums, top-level await, and const redeclaration across cells. Cells run untyped, as in Deno; typed globals are available for your editor.

npm: and jsr: imports

Install on first use into a shared cache. An optional cdp-kernel.lock.json pins every resolved version, so a notebook gets the same packages on another machine.

Project-aware

Inside a Deno project, the kernel uses its import map, node_modules and JSX settings. Inside a Workers project, env holds the project's bindings and worker is its default export.

Visual debugger

JupyterLab's debugger works on Node and Deno targets: breakpoints in the cell gutter, stepping, the call stack, scopes and variables, mapped back to your TypeScript.

Widgets and comms

anywidget-style widgets with two-way state sync in JupyterLab, Notebook 7 and VS Code, plus the comm API underneath for other protocols.

Interactive

prompt() and confirm() over stdin, interrupt that keeps state, Shift-Tab inspection and completion that never run getters, and cell history.

How each runtime works · Known gaps

Notebooks without Python

A Jupyter kernel still needs a Jupyter server, and the usual one is Python's jupyter lab. If you write TypeScript, that means installing a Python toolchain just to open a notebook.

Ganymede is a Jupyter server written in Rust. One binary serves JupyterLab's frontend and VS Code, and replaces jupyter lab, jupyter kernelspec and jupyter execute. With it, a notebook setup for cdp-kernel is Node or Deno plus Ganymede, nothing else.

Install Ganymede · Getting started

# after installing Ganymede
npm install -g @tlockney/cdp-kernel
cdp-kernel install --runtime node
ganymede lab

How it works

Deno 2.9's kernel is already two halves: the Jupyter wire protocol in plain JS, and a REPL isolate driven by CDP calls. cdp-kernel ports the protocol half to node:net and node:crypto, and points the CDP half at another runtime's inspector. esbuild and acorn replace what Deno's module loader did.

Status

Early software. It passes a conformance suite derived from Deno's own Jupyter integration tests on every target, on Linux and macOS, against Node 22, 24 and 26 and Deno 2.9 and later. Windows isn't supported yet.
